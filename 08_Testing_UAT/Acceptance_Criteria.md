# AspireX – Acceptance Criteria

## 1. Introduction

This document defines the conditions that each major AspireX feature must satisfy to be considered acceptable from a business and user perspective.

## 2. Acceptance Criteria

### AC-001: Target Career Selection
- The student can view available career paths.
- The student can select a target career.
- The selected career is saved successfully.
- The student can update the selected career.

### AC-002: Skills Assessment
- The student can enter their current skills.
- The student can specify their skill proficiency levels.
- The student can update their skill information.
- The system validates required skill information.

### AC-003: Skills Gap Analysis
- The system compares the student's current skills with the selected career's required skills.
- The system identifies missing skills.
- The system displays the skills that need improvement.
- The analysis results are understandable to the student.

### AC-004: Requirements-Match Score
- The system calculates a career requirements-match score based on the student's skills.
- The score is displayed clearly.
- The displayed score corresponds to the sample assessment data.

### AC-005: Learning Recommendations
- The system provides learning recommendations based on identified skill gaps.
- Recommendations are relevant to the selected career.
- Students can view the recommended learning resources.

### AC-006: Progress Tracking
- Students can record their learning progress.
- The system displays completed and remaining learning activities.
- Progress information is updated when students record changes.

### AC-007: Career Readiness Dashboard
- The dashboard displays the selected career.
- The dashboard displays the skills-gap summary.
- The dashboard displays the career requirements-match score.
- Dashboard information is presented clearly.

### AC-008: Power BI Reporting
- Power BI dashboards display the correct sample dataset.
- KPI calculations produce the expected results.
- Visuals update correctly when the underlying sample data changes.

## 3. Overall Acceptance Conditions

The proposed system will be considered ready for stakeholder acceptance when:
- All agreed Must Have requirements satisfy their acceptance criteria.
- No unresolved critical defects remain.
- UAT results are reviewed by relevant stakeholders.
- Stakeholders approve the solution against the agreed requirements.

## 4. Status

**Status:** Proposed – Not Yet Tested

**Note:** These criteria are defined for the AspireX fictional case study. Actual acceptance will require a working application and stakeholder UAT.
